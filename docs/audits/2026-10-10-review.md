# Technical review — 2026-10-10

Follow-up to `docs/audit-findings.md` (August 2026), whose patterns still
apply. This pass was run by one agent in one session, without sub-agents, so
it is **not exhaustive**: section A.2 lists what was examined and what was
not.

## A. Executive summary

### A.1 Overall state

The codebase is in good shape for a local-first desktop app. The patterns
the previous review introduced hold up where they were checked:

- authorization lives in the Rust commands;
- event-log writes are idempotent;
- the shared table lists are not duplicated;
- destructive actions go through `ConfirmDialog`;
- errors are translated before they reach the screen.

The Tauri surface is tight:

- the CSP is strict;
- `fs` capabilities are scoped to `$APPDATA/backups` and `$APPDATA/logs`;
- the HTTP capability only allows the Clerk domain;
- every GitHub Action is pinned by SHA.

`pnpm audit` reports no vulnerability, and CI's `cargo-audit` and `osv-scan`
jobs are green on `main`.

The most serious problems found were two **functional and security bugs**:

1. **The profile PIN lock could be bypassed.** The sidebar switcher opened a
   PIN-protected profile without asking for the PIN, and every profile
   command was callable without it. _(P1, fixed)_
2. **A series' library status stayed "Completed" when new episodes aired.**
   The same problem made series disappear from "Watch next". _(P1, fixed)_

## C. Security report

- **Confirmed and fixed:** R-04 (PIN bypass, exploitable from the UI itself)
  and R-05 (CI token privilege).
- **Open risks:** R-07 and R-08, both P3. Neither is exploitable without
  local access or a prior script injection, which the CSP blocks
  (`script-src 'self'`, no `unsafe-eval`).
- **Dependencies:** `pnpm audit` and `pnpm audit --prod` find nothing. The
  `cargo-audit` job is green on `main`; it was not run locally. One accepted
  advisory: `GHSA-vfj7-8cjw-p6xm` (braces, dev only, no patch available),
  ignored until 2027-01-10 in `osv-scanner.toml`.
- **"Code scanning configuration error — osv-scanner":** the latest
  `osv-scanner` analysis on `refs/heads/main` (2026-10-10 13:27 UTC) has no
  error. The alert matches the three CI runs that failed on 2026-10-09
  (Dependabot bumps), before commit `618cdda` added the ignore entry. There
  is nothing left to fix in the repository. If the banner persists, open
  _Security → Code scanning → Tool status_ on GitHub and remove the stale
  configuration if one is listed (manual action).
- **Checked and sound:**
  - Tauri capabilities and CSP;
  - the TMDB proxy (fixed host, path validated, token sent as a header,
    never logged);
  - profile ownership checks on lists, filters and alerts;
  - SHA-pinned actions and per-job permissions in `ci.yml`.

## G. Remaining work

   directory saved in the preferences and to `$APPDATA/backups`. Make sure
   a directory chosen in the dialog is saved before the first write.
2. **P3 — R-08.** Add a short lockout after N failed
   `verify_profile_pin` attempts and a slow hash (argon2/scrypt). This only
   matters if the threat model ever covers more than a "family lock".
3. **P3 — R-09.** Make removing the active profile atomic in Rust, by
   resetting `activeProfileId` in the same transaction and refreshing
   `PreferencesCache`.
4. **P3 — R-10 and `docs/performance.md`.** Precompute or window the

   SQL aggregates.
5. **Not covered by this pass:**

     cleanups);
   - a UX/accessibility pass;
